Version control is the way that developers use to keep track of the work that they are doing.
The way to apply version control is by using Git, a command-line version control program. By doing version control, you eliminate the problem of not knowing the final final file of your project. With version control, you know exactly where you are and you can move to wherever you want; if you make some mistake while doing a task and want to return to how it was before your changes, you can. If you want to share your complete project and track your coworkers' changes, you can, and many other things.
To me, the most useful command of Git is "git commit." It allows you to register a feature/improvement/fix to your repository. Some other common commands of Git are "git clone," used to clone a repository completely; "git status," used to know the status of the repository; and "git merge," used to combine histories/changes from different branches.
Another good thing about version control is that you can work on something called a "branch," a reserved space where you can make any changes without affecting other people's repositories.
In a development team, version control is extremely necessary. The workflow should be something like: Clone the repository > Define a branch to work on > Make changes > Commit the changes > Push to the designated repository > Pull changes to your repository.
